# Contributing

Contributions are welcome. Start by describing the recurring engineering problem and who encounters it. For changes beyond a small correction, propose the scope and acceptance criteria in an issue or pull request before expanding the implementation.

For a skill change:

1. Keep the workflow focused on one engineering problem.
2. Preserve the required sections and boundaries described in the repository [AGENTS.md](AGENTS.md).
3. Include a real or realistic usage example and report what worked, what failed, and what evidence is available.
4. Keep claims about agent compatibility tied to current host documentation or a recorded discovery test.
5. Do not include secrets, private source code, or identifying details from private projects in examples or evals.

Small documentation fixes can be submitted directly as a pull request. There are no automated test commands yet; include any relevant manual validation in the pull request description.
